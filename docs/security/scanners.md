# Automated scanner results

Free static scanners run on every push (`.github/workflows/security.yml`, Actions → **security**). These are
pattern-matching tools, not an audit: they catch known bug shapes and leave design and economic issues alone.
Every finding is listed here as **fixed**, or **accepted** with the reason. A new finding in a run that is not in
this file needs a look.

Last reviewed: 2026-11-18, commit `ae3a284`.

## Solidity: Slither on `evm/contracts/EcrinVault.sol`

31 results; none is a real issue. Every state-changing entry point is `nonReentrant`, and Lido, wstETH and
the withdrawal queue are immutable addresses set in the constructor.

| ID | Detector | Where | Verdict |
|----|----------|-------|---------|
| 0 | arbitrary-send-eth (High) | `_pay` | Accepted. ETH only leaves the caller's own vault balance, to a trusted address or after the withdrawal delay; that's the product. Covered by `nonReentrant` and the balance is debited before the call. |
| 1, 2 | reentrancy-balance (High) | `stakeEth` | Accepted. The balance-before/after pattern is deliberate (it counts only what really arrived). The calls go to Lido's own immutable contracts and the function is `nonReentrant`. |
| 3, 6 | incorrect-equality | `stakeEth` (`st == 0`, `got == 0`) | Accepted. A guard that rejects a stake that produced nothing; strict equality is intended. |
| 4, 5 | incorrect-equality | `_spend`, `_spendToken` (`day == spentDay`) | Accepted. Compares day numbers to reset the daily limit; not a balance check. |
| 7 | reentrancy-no-eth | `unstakeEth` | Accepted. The stake is debited before any call; only the request id (known after the call) is stored afterwards. `nonReentrant`; Lido's queue is trusted and immutable. |
| 8, 9 | uninitialized-local | `available`, `availableToken` (`queued`) | Accepted. Solidity zero-initializes locals; it is a running sum starting at 0. |
| 10–12 | unused-return | `submit`, `wrap`, `unwrap` | Accepted. The contract measures balance changes instead of trusting return values, which is stricter. |
| 13 | missing-zero-check | `proposePauser` | Accepted. `address(0)` withdraws a pending offer (documented); `acceptPauser` rejects the zero address. |
| 14, 15 | reentrancy-benign | `stakeEth`, `depositToken` | Accepted. Same as 1–2: balance-diff accounting under `nonReentrant`. |
| 16–25 | timestamp | delays, lock, daily limit | Accepted. Delays are hours to days; a validator's few seconds of clock leeway doesn't matter. |
| 26–28 | low-level-calls | `_call`, `_held`, `_pay` | Accepted. Needed to support tokens that return nothing (USDT); results are checked. |
| 29 | naming-convention | `IWithdrawalQueue.WSTETH()` | Accepted. That is Lido's own function name. |
| 30 | unindexed-event-address | `PauserChanged(address)` | Accepted for now (informational). Index it with the next contract change; changing the frozen contract for it isn't worth a redeploy. |
